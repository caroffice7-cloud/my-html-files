# 보성군 농산물 직거래 자사몰 플랫폼 (BMCTVda)

> 기술설계서 `260913_기술설계서_보성군농산물직거래자사몰플랫폼_v1.0` 의 **1단계 범위**를 구현한 것입니다.
> 농업회사법인 히스메이커스 주식회사 · BMCTVda · BMC 마을방송국

보성군 지역 농가·소상공인(보흥제유소, 다향농장, 주방철물)의 상품을 자사몰에 등록·판매하고,
같은 상품 데이터를 쿠팡·쿠팡파트너스·토스쇼핑 등 외부 채널로 내보내는 **위탁판매 기반 다채널 커머스 플랫폼**입니다.

핵심 원칙은 **자사몰이 상품 데이터의 단일 원천(Single Source of Truth)** 이라는 것입니다.
공급처가 상품을 한 번 등록하면 그 정보가 자사몰 판매와 외부 채널 연동에 그대로 쓰입니다.

## 1. 실행 방법

준비물은 **Node.js 22.13 이상** 하나뿐입니다. 설치(npm install)나 빌드 과정이 없습니다.

```bash
ADMIN_PASSWORD=원하는비밀번호 npm start
```

**서버에 올리기 전에 내 PC에서 먼저 보시려면** → **[docs/내PC에서-먼저-보기.md](docs/내PC에서-먼저-보기.md)**
(윈도우는 `시작하기-윈도우.bat`, 맥은 `시작하기-맥용.command` 를 더블클릭하면 됩니다)

실제 서버에 올리는 절차(설치·HTTPS·자동 백업·점검표)는 **[docs/DEPLOY.md](docs/DEPLOY.md)** 에 정리해 두었습니다.

| 화면 | 주소 |
| --- | --- |
| 소비자 쇼핑몰 | http://localhost:3000/ |
| 공급처 화면 | http://localhost:3000/supplier |
| 운영자 화면 | http://localhost:3000/admin |

### 초기 계정

공급처 계정은 실제 계약서 기준으로 미리 만들어져 있습니다. **운영 전 반드시 비밀번호를 바꾸십시오.**

| 공급처 | 아이디 | 초기 비밀번호 |
| --- | --- | --- |
| 보흥제유소 | `bohueng` | `bohueng2026` |
| 다향농장 | `dahyang` | `dahyang2026` |
| 주방철물 | `jubang` | `jubang2026` |

운영자는 **담당자별 계정**으로 로그인합니다. 최초 실행 시 `admin`(총괄) 계정이 자동 생성되며 비밀번호는 환경변수 `ADMIN_PASSWORD` 값입니다(기본값 `bmctvda2026`). 첫 로그인 시 변경을 안내하고, 분실하면 `ADMIN_RESET=1` 로 한 번 켜서 초기화합니다.
비밀번호는 scrypt 로 해시해 저장하며, 운영자 화면에서 공급처 비밀번호를 재발급할 수 있습니다.

## 2. 세 개의 화면

### 소비자 쇼핑몰

- 상품 목록·검색·카테고리 탐색, 상품 상세(사진 갤러리, 원산지·소비기한·원재료·상품정보 제공고시, 생산자 소개)
- 장바구니(브라우저에 보관) → 주문자·배송지 입력 → 주문
- 결제는 **무통장입금**과 **보성군 지역화폐** 두 가지. 지역화폐는 카드형 가맹점 결제 특성상
  "결제요청 접수 → 담당자 결제 → 승인번호 입력으로 결제확인" 흐름으로 처리합니다.
  온라인 즉시승인(PG)이 열리면 `src/lib/localcurrency.js` 의 결제확인 앞단만 교체하면 됩니다.
- 주문번호 + 연락처로 **주문 조회** (주문접수 → 공급처전달 → 출고 → 배송중 → 완료 단계 표시, 송장번호 노출)
- 신선식품 청약철회 제한, 하자·오배송 24시간 이내 접수 안내를 주문 화면에 고지

### 공급처 화면 (농가·소상공인)

- 계약 체결 공급처만 로그인
- **상품 등록** — 상품명·분류·규격·등급·원산지·소비기한·보관방법·원재료·상품정보 제공고시·공급가·권장판매가·재고·배송비, **사진 다중 업로드**
- 등록 상품 목록과 상태 확인(승인대기 / 판매중 / 반려 / 품절 / 판매중지), **반려 사유 표시**
- 판매중 상품의 내용을 고치면 자동으로 다시 검수 대상이 됩니다
- **주문 · 발송** — 발송해야 할 주문 목록, 송장번호 입력 시 주문이 자동으로 "출고" 처리
- **판매 현황 · 정산** — 기간별 판매금액·수수료·정산 예정액, 확정된 정산서 내역
- **계약 조건 조회** — 내 판매수수료율·정산주기·배송방식·할인 허용 한도를 항상 확인 가능
- 사업자 정보 수정, 비밀번호 변경

### 운영자 화면 (히스메이커스)

| 메뉴 | 내용 |
| --- | --- |
| 대시보드 | 승인 대기 상품, 공급처 전달 대기 주문 경고, 이번 달 판매금액·수수료 수익, 공급처별·채널별 실적 |
| 상품 승인 · 관리 | 검수 후 승인/반려(사유 필수), 전체 공급처 상품 통합 조회·수정, 상품 CSV 내보내기 |
| 채널 연동 | 상품 × 채널 노출 현황 한눈에 보기, 채널별 판매가·채널 URL 관리, 채널별 업로드용 CSV |

| 수수료 관리 | **공급처별·상품별 판매수수료율을 건별로 입력**, 협의 메모와 함께 일괄 저장, 변경 이력 조회 |
| 정산 | 공급처별 판매금액·수수료·반품 집계 → **정산서 생성**(미정산 건 마감) → 지급 완료 처리, 정산서 CSV |

| 운영자 계정 | 담당자별 계정 발급·역할 지정·비밀번호 재발급·사용 중지, 변경 기록 조회 (총괄만) |

## 3. 계약 조건이 시스템에서 동작하는 방식

위탁판매 계약 조건은 문서가 아니라 **데이터로 관리되며, 실제 계산과 통제에 그대로 쓰입니다.**

| 계약 조항 | 시스템 동작 |
| --- | --- |
| 판매수수료율 | 주문이 생길 때 **상품 개별율 → 공급처 기본율** 순으로 적용해 수수료와 정산액을 계산하고 주문 항목에 기록 |
| 반품·환불 비용 부담 (제7조) | 반품 처리 시 사유에 따라 부담 주체(공급처 / 소비자 / 히스메이커스)를 기록하고, **공급처 부담 비용만 정산 지급액에서 공제** |
| 할인 허용 한도 (권장판매가 대비 %) | 채널 판매가를 한도 밑으로 내리면 **저장이 차단**되고, 공급처 사전 동의를 확인한 경우에만 사유를 남기고 저장 |
| 정산 주기 (익월 15일) | 정산서 생성 시 지급 예정일을 자동 산정, 수수료·반품액·공급처 부담 비용을 공제(제8조) |
| 위탁배송 (공급처 직발송) | 배송비를 **공급처 단위로 부과**, 공급처가 송장을 입력하면 출고 처리 |
| 출고 기한 (영업일 N일) | 공급처 화면 발송 목록에 기한을 안내 |
| 주문 전달 영업일 1일 이내 | 운영자 대시보드에서 전달 대기 주문을 경고로 표시 |

적재된 계약 조건은 실제 계약서를 그대로 반영했습니다.

| 공급처 | 판매수수료 | 정산 | 출고 | 할인 한도 |
| --- | --- | --- | --- | --- |
| 보흥제유소 | 25% | 익월 15일 | 영업일 2일 | 20% |
| 다향농장 | 기본 20% (신선·가공·선물세트) / 체험 이용권은 상품 개별율 15% | 익월 15일 (체험은 이행 월 기준) | 영업일 1일 | 20% |
| 주방철물 | **계약서 공란 — 미확정** | 익월 15일 | 영업일 2일 | **계약서 공란 — 미확정** |

> 주방철물은 계약서 제9조(판매수수료율)와 제6조(할인 한도)가 공란이어서 **미확정**으로 넣어 두었습니다.
> 미확정 상태에서는 수수료가 0원으로 계산되며 운영자 화면에 경고가 표시됩니다.
> 농가·소상공인과 협의가 끝나는 대로 **수수료 관리** 화면에서 바로 입력하시면 됩니다.

### 수수료율은 두 단계로 관리합니다

보성군 내 농가·소상공인과 개별 협의로 요율을 정하는 방식이므로, 요율을 계약서에 고정하지 않고
운영자가 언제든 바꿀 수 있게 만들었습니다.

| 단계 | 적용 범위 | 입력 위치 |
| --- | --- | --- |
| **공급처 기본율** | 그 공급처의 모든 상품 | 공급처 · 계약 화면, 또는 수수료 관리 화면 |
| **상품 개별율** | 특정 상품만 다르게 합의한 경우 | 수수료 관리 화면, 또는 상품 상세 |

- 주문이 들어오면 **상품 개별율 → 공급처 기본율 → 미확정(0%)** 순으로 적용됩니다.
- 요율은 **%로 입력**합니다(`20`). `0.2` 로 넣어도 같은 값으로 저장됩니다.
- 비워 두면 "미확정"으로 남고, 수수료가 0원으로 계산되며 화면에 경고가 뜹니다.
- 언제 누가 몇 %로 바꿨는지 **변경 이력**이 협의 메모와 함께 남습니다.
- 한 공급처의 상품 개별율을 한 번에 지우고 기본율로 되돌리는 버튼도 있습니다.
- 아직 계약 전이라면 공급처 상태를 **협의중**으로 두고 사이트를 보여주며 협의할 수 있습니다.

상품은 각 계약서 `[별지 1]` 의 품목명만 등록해 두었고 **공급가·권장판매가는 비워 두었습니다.**
별지에 금액이 기재되어 있지 않아 임의의 단가를 넣지 않았습니다. 공급처가 직접 입력한 뒤 승인 요청하면 판매가 시작됩니다.

## 보안 · 업로드

소비자 개인정보와 공급처 사업자 정보를 다루므로 다음을 적용했습니다.

| 항목 | 처리 |
| --- | --- |
| 로그인 | 운영자는 담당자별 계정(scrypt 해시), 공급처는 계약 공급처 계정. 같은 IP에서 10분 내 5회 실패하면 10분간 잠금 |
| 공급처 비밀번호 | scrypt 해시로 저장, 평문 보관 없음 |
| 세션 | HttpOnly · SameSite=Lax 쿠키, 8시간 만료. HTTPS 운영 시 `SECURE_COOKIE=1` |
| 접근 통제 | 공급처는 자기 상품·주문·정산만 조회·수정 가능. 운영자는 역할(총괄/담당자)에 따라 기능 제한 |
| 변경 기록 | 상품 승인·주문 처리·수수료 변경·정산서 생성을 담당자·시각·IP와 함께 보관 |
| 화면 출력 | 화면에 넣는 값을 HTML 이스케이프 처리 |
| 금액 계산 | 판매가·수수료를 클라이언트 값이 아닌 서버 기준으로 다시 계산 |
| 사진 업로드 | JPG·PNG·WEBP·GIF만 허용(SVG 제외), 장당 4MB·한 번에 8장, 무작위 파일명 저장 |

**사진은 브라우저에서 자동으로 줄여서 올립니다.** 휴대폰 사진은 보통 3~12MB라 그대로 올리면
시골 회선에서 오래 걸리고 저장 공간도 낭비되므로, 긴 변 1600px JPEG로 변환한 뒤 전송합니다.
(실측: 12.4MB 사진 → 0.7MB 전송, 683KB 저장)

**HTTPS 없이 운영하지 마십시오.** 설정 방법은 [docs/DEPLOY.md](docs/DEPLOY.md) 4장에 있습니다.

## 운영자 계정과 권한

담당자마다 아이디를 발급해 **누가 무엇을 했는지** 기록이 남습니다.

| 역할 | 할 수 있는 일 |
| --- | --- |
| **총괄** | 모든 기능 + 운영자 계정 관리 + 공급처·계약 관리 + 수수료율 변경 + 정산서 생성·지급 처리 + 설정 |
| **담당자** | 상품 승인·관리, 주문 관리, 채널 연동, 정산 조회 |

- 돈이 나가는 일(정산서 생성·지급 완료)과 계약 조건·수수료율 변경은 **총괄만** 할 수 있습니다.
- 총괄 관리자는 **최소 한 명**이 유지되도록 강제됩니다.
- 계정을 중지하거나 비밀번호를 재발급하면 해당 계정의 로그인이 즉시 끊깁니다.
- 상품 승인·반려, 주문 상태 변경, 수수료율 변경, 정산서 생성이 **변경 기록**에 남습니다.

## 4. 기술 구성

외부 라이브러리 없이 **Node.js 표준 모듈만** 사용합니다(`node:http`, `node:sqlite`, `node:crypto`).

```
server.js               HTTP 서버 · 라우팅 · 정적 파일
src/db.js               SQLite 스키마
src/seed.js             공급처 3곳 · 계약 조건 · 계약서 별지 품목
src/lib/http.js         라우터, JSON/CSV 응답, 쿠키
src/lib/auth.js         관리자 세션 + 공급처 계정(scrypt 해시)
```

## 6. 운영 전 확인이 필요한 사항

설계서 6장 "미결정 사항" 중 코드로 정할 수 없는 항목입니다.

1. **지역화폐 가맹 등록** — 지역화폐 결제 기능은 만들어져 있으나, 실제로 받으려면
   지자체 가맹점 등록·업종코드 확인·통신판매업 신고가 먼저입니다. 등록 전에는 설정 화면에서 '중지'로 두세요.
2. **PG사 선정** — 온라인 카드 즉시결제를 붙이려면 PG 계약이 별도로 필요합니다.
2. **호스팅·도메인** — Node 상주형 서버(카페24 Node 호스팅, AWS Lightsail, Render 등)에 적합합니다.
   서버리스로 가려면 SQLite 대신 외부 DB로 바꿔야 하며, `src/db.js` 한 파일만 교체하면 되도록 분리해 두었습니다.
   업로드된 사진도 파일 시스템에 저장되므로 서버리스에서는 오브젝트 스토리지가 필요합니다.
3. **수수료율** — 주방철물을 비롯해 앞으로 합류할 공급처의 요율은 협의가 끝나는 대로 운영자 화면 > 수수료 관리에서 입력하면 됩니다(코드 수정 불필요).
4. **쿠팡 오픈API** — 신청·승인 절차와 사업자 요건 확인이 선행되어야 2단계 자동 연동이 가능합니다.
5. **통합돌봄 시스템과의 데이터 공유** — 설계서에 "추후 검토"로 남은 항목입니다.
   현재는 완전히 분리된 별도 시스템이며, 생활장터 장보기 품목과 자사몰 상품은 각자의 데이터베이스를 씁니다.

## 보성군 지역화폐 결제

농산물 마켓을 지역화폐와 결합한 부분입니다. 카드형 지역화폐는 가맹점 단말기 결제가 원칙이라,
1단계에서는 온라인 즉시승인 대신 **결제요청 → 담당자 결제 → 승인번호 입력** 흐름으로 처리합니다.

### 결제 흐름

| 단계 | 화면 | 내용 |
| --- | --- | --- |
| 1 | 소비자 | 결제수단에서 지역화폐를 고르고 결제 방식(방문 카드단말기 / 매장 방문 / 모바일)을 선택해 주문 |
| 2 | 소비자 | 주문완료 화면에 결제 예정 금액과 안내문이 표시됨 (아직 미결제) |
| 3 | 운영자 | **지역화폐 결제** 화면의 "결제 대기" 목록에서 해당 주문 확인 |
| 4 | 운영자 | 카드단말기로 결제한 뒤 영수증의 **승인번호**를 입력 → 결제확인 |
| 5 | 운영자 | 결제확인이 되어야 **공급처전달**로 넘어갑니다 (미결제 발송 차단) |

### 어떤 상품을 지역화폐로 살 수 있는가

수수료율과 같은 **2단계 구조**입니다.

```
사용 가능 여부 = 상품 개별 설정 → (없으면) 공급처 가맹 설정
```

- 공급처 가맹 여부는 **공급처 · 계약** 화면에서 지정합니다 (기본값: 사용 가능)
- 품목 제한이 있는 상품만 **상품 관리**에서 따로 덮어씁니다
- 장바구니에 지역화폐 불가 상품이 하나라도 있으면 지역화폐 결제가 막히고, 이유가 화면에 표시됩니다

### 운영자 화면

- **결제 대기** — 승인번호 미입력 주문 목록, 결제확인 버튼
- **결제 완료 내역** — 기간 조회, 승인번호·결제방식·결제일시, **CSV 내려받기**(지자체 제출·대사용)
- **공급처별 지역화폐 판매** — 공급처마다 지역화폐로 팔린 금액
- **가맹 설정 현황** — 공급처별 사용 가능 여부 한눈에 보기
- 대시보드에 **이번 달 지역화폐 결제액**과 **결제 대기 건수**가 표시됩니다

### 설정 (설정 화면)

| 항목 | 설명 |
| --- | --- |
| 지역화폐 결제 받기 | 사용 / 중지. 가맹 등록 전에는 중지로 둡니다 |
| 지역화폐 이름 | 소비자 화면에 표기할 이름 (예: 보성사랑상품권(카드형)) |
| 가맹점 번호 | 지자체 발급 가맹점번호 |
| 배송비도 지역화폐로 결제 | 포함 / 제외 |
| 1회 결제 한도 | 0이면 제한 없음 |
| 주문 완료 화면 안내문 | 소비자에게 보여줄 문구 |

### 안전장치

- 결제수단·결제 가능 여부는 **서버에서 다시 판정**합니다 (클라이언트 값 불신)
- 결제금액이 주문금액을 넘으면 거부
- 승인번호 없이는 결제확인 불가, 결제확인 없이는 공급처 전달 불가
- 결제확인·취소·가맹 설정 변경은 모두 **감사 로그**와 주문 처리이력에 남습니다
